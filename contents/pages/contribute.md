HeyBlog 接受围绕博客目录、项目文档、程序实现和社区协作的贡献。参与前请阅读 [社区公约](/community)；注册账号或提交站点资料时，还应阅读 [用户服务与内容提交协议](/terms)。

## 目录与数据

你可以：

- 提交尚未收录的个人博客。
- 修订站点名称、简介、分类、标签、订阅地址等公开资料。
- 反馈失效、重复、迁移或需要下架的目录条目。
- 协助核对站点、订阅源、站点地图和友链页面的公开可访问状态。

提交前请阅读 [博客收录与审核说明](/docs/collection-standards) 和 [数据字段与分类说明](/docs/data-field-guide)，再前往 [站点提交](/site/submit)。

## 文档与程序

- 文档、静态数据及组织公共配置位于 [heyblog/.github](https://github.com/heyblog/.github)。
- 网站程序、页面渲染和相关服务位于 [heyblog/web](https://github.com/heyblog/web)。
- 自动发现与网站检测的运行边界见 [站点发现与检测说明](/docs/site-discovery-and-checking)。

请先阅读目标仓库的说明、贡献要求和许可证。仓库提供自己的规则时，以该仓库规则为准。

## 成员身份与贡献记录

提交代码、文档、数据、问题反馈或其他协作内容，不会自动取得项目组成员身份。经沟通确认正式加入的当前、暂离及历史成员由静态成员数据维护；项目合并前的历史贡献者致谢名单作为冻结快照保留；当前外部贡献者展示功能启用后，仅根据 HeyBlog 相关 GitHub 仓库的公开贡献记录通过 GitHub API 自动维护。

经沟通确认加入项目组后，新成员本人应按 [加入项目组的欢迎流程](/docs/contribution-guide#加入项目组的欢迎流程) 提交成员资料 Pull Request。该流程用于公开登记和欢迎，不是成员申请入口，也不自动授予仓库权限或对外代表权。

## 提交要求

- 说明修改目的、影响范围、数据来源和验证结果。
- 仅提交完成事项所需的信息，不提交密码、密钥、完整身份证件或无关个人信息。
- 确认提交内容由你创作、已经取得必要授权，或依法可以在相应范围内使用。
- 第三方资料应标明来源，不得将公开可访问等同于可以任意复制或重新发布。
- 避免重复提交；需要补充时，在原有改动或邮件中继续说明。

项目可以依据公开标准要求补充材料、调整格式、拒绝不符合范围的内容，或者对错误、侵权和存在安全风险的内容采取隐藏或移除措施。

声明文档、项目文档及其相关原创图像的许可见 [版权声明](/copyright)。代码、配置和其他内容以所在仓库或文件标明的许可证为准。

## 联系方式

普通 Bug、功能建议和其他可公开讨论的开发问题提交到对应仓库的 Issue；网站程序、页面渲染或接口问题提交到 [heyblog/web Issues](https://github.com/heyblog/web/issues)。新博客收录申请仍通过 [站点提交](/site/submit) 办理。

目录资料修订、停止抓取、下架、隐私、版权、社区举报及其他不宜公开的事项按 [支持与反馈说明](https://github.com/heyblog/.github/blob/main/SUPPORT.md) 通过对应入口或项目邮箱办理。目标仓库未开放 Issue 时，邮箱可作为后备渠道。

## 适用范围

本声明说明 HeyBlog 如何取得、整理、展示和维护博客目录数据，以及站点运营者如何提出纠错、限制抓取和下架请求。

能够识别自然人的信息同时适用 [隐私、Cookie 与个人信息权利声明](/privacy)；第三方内容和项目原创内容的权利归属适用 [版权、许可与侵权下架声明](/copyright)；自动访问边界见 [HeyBlogBot 爬虫与网站检测协议](/crawler)。

## 数据范围

HeyBlog 仅处理站点主动公开且与博客收录、展示、检索和检测直接相关的信息，主要包括：

- 站点名称、网址、域名、公开简介、分类和标签。
- RSS、Atom、JSON Feed 等订阅地址。
- 站点地图、友情链接页面及其他公开入口。
- 公开展示的站点标识、程序或技术信息。
- HTTP 状态、重定向、内容类型、响应时间、更新时间、检测时间和维护状态。
- 收录来源、发现关系，以及审核、纠错、去重和执行停止抓取所需的最少记录。
- 基于上述数据形成的数量、分类和可访问状态等汇总结果。

HeyBlog 不以复制、建立镜像或替代第三方博客正文为目的。第三方文章、图片、音视频和订阅全文不会仅因被发现、解析或链接而成为 HeyBlog 的内容。

## 数据来源

目录资料可能来自：

1. 博客站长、用户或项目贡献者主动提交。
2. 博客主页、公开简介、订阅源、站点地图和公开友链。
3. `HeyBlogBot` 沿已收录博客公开友链发现的候选站点。
4. 允许在合理范围内使用的公开博客目录。
5. 项目为确认信息和可访问状态进行的人工检查。

“公开”是指无需登录、授权或绕过技术限制即可正常取得。HeyBlog 不访问非公开区域，不绕过验证码、访问控制或其他限制，也不从其他渠道补充真实姓名、身份证号、住址等与目录维护无关的信息。

## 使用目的

上述数据用于：

- 判断候选站点是否符合博客目录的基本范围。
- 展示和检索博客名称、地址、简介、分类及公开入口。
- 完善缺失字段、合并重复记录和跟踪站点迁移。
- 检查站点、订阅源、站点地图和友链页面的公开可访问状态。
- 形成目录规模、分类和状态等汇总信息。
- 处理资料纠错、停止抓取、下架和恢复请求。

HeyBlog 不使用目录中的联系方式发送未经请求的信息，不根据博客内容推断站长的真实身份、年龄、健康、财务或其他敏感情况，也不将检测结果表述为质量、信用或安全认证。

## 公开信息与个人信息

公开站点资料仍可能包含作者名称、头像或联系方式等个人信息。HeyBlog 仅在目录目的所需的合理范围内处理，不因信息已经公开而扩大使用范围。

如果公开页面包含身份证号、详细住址、私人联系方式或其他与目录维护无关的信息，项目不会将其设置为目录字段。已经误收录或不宜继续展示的信息，可以通过本声明的请求渠道更正、隐藏或删除。

项目不主动识别站长是否为未成年人，也不根据页面内容推断年龄。已知涉及不满十四周岁用户的信息时，按 [隐私声明中的未成年人个人信息规则](/privacy#未成年人个人信息)处理。

## 权利与许可边界

目录中不同内容可能适用不同权利：

| 内容类别 | 权利边界 |
| --- | --- |
| 网址、HTTP 状态等事实性信息 | 事实本身未必受著作权保护，但仍可能涉及个人信息、商标或其他权益 |
| 第三方简介、标识、摘要和图片 | 权利归原作者或相应权利人，公开可访问不等于获得复制或重新发布许可 |
| HeyBlog 原创说明、字段设计、分类和编排 | 按 [版权声明](/copyright) 中标明的许可处理 |
| 状态和汇总结果 | 仅反映特定时间、数据来源和处理方法，不构成认证或保证 |
| 审核与限制记录 | 原则上不公开，仅用于维护、去重、争议处理和执行退出请求 |

页面可见、接口可请求或仓库可访问，不表示其中全部内容采用统一的数据许可证。第三方使用目录数据前，应分别确认数据来源、第三方权利、项目许可、技术限制和适用法律。

未经明确说明，网站内部接口不视为稳定、持续或已经授权的公共 API。批量复制、持续同步、重新分发、建立镜像或用于模型训练前，应先取得相应权利和授权。

## 纠错、限制抓取与下架

站点运营者、内容作者或其他相关权利人可以请求：

- 更正站点名称、简介、分类、订阅地址或其他错误资料。
- 限制展示不必要的字段。
- 停止 `HeyBlogBot` 对指定站点的后续访问。
- 下架目录条目或断开特定内容链接。
- 对误下架或误判结果提出恢复申请。

请求请发送至 [contact@mail.heyblog.net](mailto:contact@mail.heyblog.net)，建议邮件标题使用 `[资料纠错或下架]` 或 `[停止抓取]`，并提供站点地址、处理诉求和必要依据。

## 核验与处理

为防止冒用，项目可以通过以下低风险方式确认请求人与站点的关系：

- 使用站点域名邮箱回复确认。
- 在站点公开页面放置一次性验证信息。
- 添加临时 DNS 记录。
- 提供能够证明管理权限的其他必要信息。

一般不要求提供身份证件。无法确认控制关系时，项目仍可以先行隐藏明显错误、侵权或可能造成较高风险的信息，再继续核验。

收到信息基本完整的请求后，项目会结合公开来源、站点控制关系、第三方权利、现有记录和适用法律，决定更正、限制抓取、隐藏、下架、维持或恢复。

为执行退出请求并防止再次自动收录，可以保留站点地址、限制状态、时间和必要依据；该记录不用于继续展示站点资料。
